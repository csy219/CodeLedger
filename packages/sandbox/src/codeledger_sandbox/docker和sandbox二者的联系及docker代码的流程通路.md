### 一、先搞懂两个基础概念

#### 1. Sandbox（沙箱）是什么？有什么用？

**沙箱本质是一个「密封、隔离、受限的执行环境」**。
你可以把它理解成一个玻璃罩子：把程序 / 命令放进罩子里运行，无论里面的程序怎么折腾（删文件、死循环、下载恶意内容），都只能在罩子内部生效，绝对破坏不了罩子外面你电脑的系统和文件。

**核心作用：**

- **安全隔离**：跑不可信的代码 / 命令（比如 AI 生成的代码、陌生人的脚本），防止它破坏你的电脑、窃取数据。
- **资源限制**：限制程序能用多少 CPU、内存、进程数，防止恶意代码把你电脑卡死机。
- **干净可复现**：每次启动都是全新的干净环境，不会因为上一次运行的残留影响结果。
- **易销毁**：出问题直接把整个沙箱删掉，不会在你系统里留垃圾。

#### 2. Docker 是什么？有什么用？

**Docker 是一个「容器化技术工具」**，可以快速、轻量地创建出一个个相互隔离的 “微型系统”（叫容器）。
每个容器有自己独立的文件系统、进程空间、网络配置，但共用你电脑的系统内核，启动只需要几秒，占用只有几十兆。

**核心作用：**

- **环境打包**：把运行环境（Python、工具、依赖）打包成一个镜像文件，在哪跑都是一模一样的环境，不会出现 “在我电脑上能跑在你电脑上不能跑” 的问题。
- **原生隔离**：自带进程、文件、网络、资源的隔离能力，是现成的 “隔离罩”。
- **快速启停**：容器启动、销毁都是秒级，用的时候开，用完就删，非常灵活。

### 二、为什么 Docker 和沙箱要结合在一起？

简单说：**Docker 负责造 “隔离罩”，沙箱是这个 “隔离罩” 的用途**。

如果自己从零写一个沙箱，要自己做文件隔离、进程隔离、网络隔离、资源限制，非常复杂还容易出漏洞。而 Docker 天生就把这些能力都做好了，直接用 Docker 来实现沙箱，有几个无可替代的好处：

1. **安全能力成熟**：Docker 的隔离机制是工业级的，比自己写的安全得多。
2. **环境一致**：沙箱环境打包成镜像，每次启动都是完全相同的干净环境，结果可复现。
3. **成本极低**：启动一个沙箱容器只需要 1 秒，占用资源极小，可以频繁创建销毁。
4. **配置灵活**：网络、CPU、内存、权限都可以通过参数一键配置，不用改代码。

对应到你的项目：AI 代理要改代码、跑测试、执行命令，这些操作都是不可信的，绝对不能直接在你电脑上跑。用 Docker 做一个沙箱，让 AI 所有操作都在容器里，就算代码写错了、有恶意，也只会影响容器，你的电脑毫发无损。

### 三、这一整段代码的作用是什么？

这是**一套用 Docker 实现的 Python 版安全沙箱工具包（SDK）**。

它把 Docker 的复杂命令、安全配置、资源限制、超时自动清理、结果格式化这些底层细节全部藏起来，对外只暴露一个非常简单的 `run()` 函数。
你不用懂任何 Docker 命令，只要告诉它「要执行什么命令」「用哪个文件夹当工作目录」，它就会：

1. 自动找到你电脑的 Docker
2. 自动创建一个带安全限制的隔离容器
3. 在容器里执行你要的命令
4. 捕获命令的输出、退出码
5. 执行完自动销毁容器，不留痕迹
6. 把结果整理成统一格式返回给你

### 四、完整全流程例子（看完就懂整个过程）

#### 场景：让 AI 改完代码，在沙箱里跑测试验证

假设你本地有个 Python 项目文件夹：`D:\code\my-project`，AI 改完代码后，需要在里面跑 `pytest` 测试是否通过。

##### 第 1 步：你调用沙箱

```
from codeledger_sandbox import DockerSandbox

# 创建一个沙箱实例（默认配置：1核2G、禁网、120秒超时）
sandbox = DockerSandbox()

# 让沙箱在指定目录里跑pytest测试
result = sandbox.run(
    command="pytest tests/",
    workspace=r"D:\code\my-project"
)
```

##### 第 2 步：SDK 内部自动做这些事（你完全感知不到）

1. **找 Docker**：调用 `_resolve_docker_bin()`，自动找到你电脑里 `docker.exe` 的位置。
2. **校验目录**：检查 `D:\code\my-project` 这个文件夹真的存在。
3. **起名字**：给这次的容器生成一个唯一名字，比如 `codeledger-a1b2c3d4e5f6`。
4. **拼安全命令**：拼接出一整条 `docker run` 命令，带上所有安全限制：
   - 禁网络：容器里不能上网，防止 AI 下载恶意东西
   - 只读系统：容器里的系统文件不能改，只能改你挂载的代码目录
   - 限制资源：最多用 1 核 CPU、2G 内存、256 个进程
   - 普通用户：用低权限的`sandbox`用户跑，不是管理员
   - 挂载目录：把你本地的 `D:\code\my-project` 映射到容器里的 `/workspace`
5. **启动容器**：调用 Docker 启动容器，容器里自动执行 `pytest tests/`。

##### 第 3 步：执行结束，返回结果

- **正常情况**：测试跑了 30 秒跑完，容器自动删除，返回结果：
```
result.exit_code    # 0 表示测试通过
result.stdout       # pytest的测试输出日志
result.timed_out    # False
```
- **超时情况**：测试死循环了，跑了 120 秒还没结束，SDK 会**强制删掉容器**，返回：
```
result.exit_code    # 124 约定代表超时
result.stderr       # "sandbox timed out"
result.timed_out    # True
```

##### 最终效果

整个过程中，pytest 全程在隔离容器里运行，就算测试代码里有 `rm -rf /` 这种危险命令，也只会删掉容器里的东西，你电脑的系统、文件完全不受影响。跑完容器自动销毁，什么都不残留。

### 五、每个函数 / 类分别是干嘛的？

表格

| 名称 | 类型 | 核心作用 |
| --- | --- | --- |
| `_resolve_docker_bin()` | 内部工具函数 | 自动找你电脑上 docker.exe 在哪，不用手动配环境变量，三级兜底策略保证能找到 |
| `_as_text()` | 内部工具函数 | 把命令输出统一转成字符串，解决字节 / 字符串 / 空值的类型不匹配问题 |
| `SandboxConfig` | 配置类 | 沙箱的参数配置表：镜像、CPU、内存、超时、网络开关，实例创建后就不能改 |
| `SandboxResult` | 结果类 | 执行完命令的标准化返回值：退出码、输出、是否超时、容器名，全系统通用 |
| `DockerSandbox` | 主类 | 沙箱的核心类，对外提供服务，创建实例后调用 `run()` 就能跑命令 |

### 六、`run()` 方法里面到底在干嘛？

`run()` 就是整个沙箱的「总指挥」，完整走一遍「创建→执行→回收」全流程，一共 8 步：

#### 1. 校验工作目录

先把你传的文件夹转成绝对路径，检查它是不是真的存在。不存在就直接报错，避免后面 Docker 挂载失败。

#### 2. 生成唯一容器名

用 UUID 生成一个独一无二的容器名字，防止和其他容器重名冲突，也方便后面超时的时候精准删除。

#### 3. 拼接 Docker 命令参数（最核心的安全部分）

把所有安全规则、资源限制、目录挂载都拼成 `docker run` 的参数。这一步就是把 “隔离罩” 的安全锁全部扣上：

- `--rm`：跑完自动删容器
- `--network none`：断网
- `--cpus/--memory/--pids-limit`：限制资源
- `--cap-drop ALL / --security-opt no-new-privileges`：剥夺所有系统权限
- `--read-only`：系统文件只读
- `--tmpfs /tmp`：临时目录用内存盘，不落地
- `--user sandbox`：用低权限用户跑
- `-v 你的目录:/workspace`：把你的代码文件夹映射进容器

#### 4. 注入环境变量

如果你传了额外的环境变量，就逐个加到命令参数里。

#### 5. 拼接要执行的命令

用 `bash -lc` 去执行你传的命令，保证支持管道、重定向等完整的 Shell 语法。

#### 6. 启动进程执行命令

调用系统进程跑这条 Docker 命令，捕获标准输出和错误输出，同时设置超时时间。

#### 7. 超时异常处理

如果命令跑超时了，**必须强制删除容器**，不然容器会一直在后台跑，占资源。删完之后返回一个标记了超时的结果。

#### 8. 封装结果返回

正常跑完的话，把退出码、输出、容器名封装成 `SandboxResult` 对象返回给你。
